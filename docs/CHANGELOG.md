### 优化

- 首字延迟从 **85 秒降到 34-44 秒**（输入 token 从 1599 降到约 700）
- 修复流式输出被吞的问题：去掉「积累 200 字才输出」的门槛，Qwen 短回答不再丢失

### 工程
- 新增 `CONTRIBUTING.md`：注释规范（逻辑行必须中文注释）、提交规范、三处同步要求
- 新增 `tools/sync.ps1`：一条命令完成「本地 → GitHub → 服务器」同步并校验 MD5
- 新增 `tools/gen_func_map.py` 与 `docs/FUNC_MAP.md`：自动生成函数调用关系表
- `tools/serve_r1.py` 全部逻辑行加中文注释，并改为相对路径（Windows/Linux 通用）

## 2026-11-07（补充）

### 注释工程（第二批）
- src/nanogpt.c 全文件逻辑行加中文注释：前向/反向传播、AdamW、梯度检查、
  词表构建、采样生成、权重存取、对话模式、表达式解析器、main 分派
- 注释覆盖率从 0 提升到约 68%（1426 行中有 968 行带注释）

### 修复（加注释过程中发现的既有 bug）
- **小语料训练崩溃**（0xC0000005 访问违规）：
  sample_batch() 里 \hi - lo - T - 1\ 在验证集短于上下文长度时为负数，
  转 unsigned 取模后得到天文数字，导致越界读。
  修法：跨度先算出来，\<= 0\ 时夹到 1；同时在切分时保证验证集至少留 T+2 个 token。
- 验证：修复前用 1.8K 字符语料训练必崩，修复后正常训练并保存权重（退出码 0）。

### 验证方法
- 用 \git show HEAD:src/nanogpt.c\ 取出注释前版本，同参数编译运行，
  确认梯度检查数值、训练 loss 逐字节一致 → 证明加注释没有改变任何行为。

- 原件备份为 corpus_math_backup.txt，可用 merge_literature.py 重新合并（幂等）

### 改进：检索算法改用 IDF 加权
- 问题：原算法要求"共同二元组 ≥ 3"才算命中，「静夜思的作者是谁」只能重合
  "静夜""夜思" 2 个，导致明明有资料却检索不到
- 改法：统计每个二元组的文档频率，按 IDF 加权求和打分；改为"至少 2 个共同二元组 + IDF 总分排序"
- 效果：文学问题全部能命中；数学问题检索不受影响（正交矩阵仍命中教材原文）

- literature.txt（诗文语料）、literature_knowledge.txt（文学常识）、corpus_math_backup.txt（数学语料备份）
